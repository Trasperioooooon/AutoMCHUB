# MineDeck v2.9.0 测试版的测试计划

这份计划写于 2026-10-31，现在对应 GitHub 上的预发布版 [v2.9.0-beta.2](https://github.com/Trasperioooooon/MineDeck/releases/tag/v2.9.0-beta.2)。它是自包含的：不了解这个项目的人或 AI，照着它也能从头测到尾。

- 房主（项目作者本人）：按这份计划测，可以让本机的 AI 智能体帮忙。
- 独立测试员（比如 ChatGPT 或国内的智能体）：先读第 3 节，再按第 4 节的顺序测。
- 只来进服帮忙的好友：看更短的[《好友测试指南》](好友测试指南.md)就够了。

发现的问题都按第 5 节的格式记下来。

## 1. 先看这里

### 1.1 这一版测什么

MineDeck 是 Windows 上的 Minecraft 一键开服工具，单文件 `MineDeck.exe`。和上一个正式版 v2.6.1（当时叫 AutoMCHUB）相比，这一版的变化如下：

- **改名**：AutoMCHUB 改名为 MineDeck，要处理老用户升级。
- **界面 v5**：新的视觉、图标、内嵌字体和启动画面。
- **架构调整**：所有界面操作都改走一层统一的「操作层」，接口不变；CurseForge Key 和穿透凭据改成加密保存。
- **五个新功能**，都是可选的：
  - AI 接入；
  - 应用内 AI 助手和报错横幅；
  - 游戏内 AI；
  - 音乐共享和 AI 伙伴；
  - MCP 接口（beta.2 起）：让电脑上的其他 AI 工具用 MineDeck。

测过 beta.1 的，beta.2 重点测这几处：J 组「MCP 接口」整组；H 组里写着「0.2.1 起」的几条（伙伴停下后在水里不淹死、给东西按实际交出的个数报结果、重启后一连上就列出伙伴）。

### 1.2 已经测过的，不用重复

- Go 单元测试：在 GitHub 的 Windows 机器上每次推送都跑（`.github/workflows/test.yml`）。
- 前端交互测试：65 条，在 Linux 的 Chromium 里跑，用的是仿真后端。
- AI 部分：用假的 AI 服务回放各家官方格式的样本。
- 游戏内 AI 和音乐共享：用假的服务器进程、假的语音模组测过。
- AI 伙伴：MineDeck 的真代码和真的伙伴模组在云端的无头 NeoForge 1.21.1、Forge 1.20.1 服务器上联调过（玩家是机器人，AI 是假的），刷出、采集、跟随、给东西、停下、移除、断线重连和重启接管都通过。
- MCP 接口：用官方的 Go 和 TypeScript 客户端库，对 wine 里跑的 release 版连过 HTTP 和 stdio 两种方式。

这些都没碰过的，是这次要测的：真的 Windows 窗口、真的 Minecraft 服务器和客户端、真实的 AI Key、真的玩家，以及国内的网络。

### 1.3 优先级

- **P0**：发正式版前必须通过。
- **P1**：应该测。
- **P2**：有条件再测。

测试项后面方括号里写着需要什么条件：

| 标记 | 需要什么 |
|---|---|
| [Win11] / [Win10] | 这个版本的 Windows |
| [真 Key] | 真实的 AI 服务商 API Key |
| [客户端] | 一个 Minecraft 客户端 |
| [两个号] | 两个游戏账号同时在线 |
| [好友] | 另一台电脑上的玩家 |
| [手机] | 和电脑连同一个 Wi-Fi 的手机 |
| [樱花] | 樱花穿透（SakuraFrp）账号 |
| [旧版] | 用过 v2.6.1（AutoMCHUB.exe）的文件夹 |
| [MCP 客户端] | 支持 MCP 的 AI 工具：Claude Desktop（stdio），Cherry Studio、Cursor 或 VS Code（HTTP），最好两种方式各一个 |

## 2. 准备

### 2.1 电脑

- 一台 Windows 11 电脑，建议 16 GB 内存，测试用的服务器要占 4–6 GB。有 Windows 10 的电脑可以补测几项。
- 新建一个空文件夹，比如 `D:\MineDeck-beta`，把 `MineDeck.exe` 放进去。所有数据都存在 exe 旁边，测完删掉这个文件夹就干净了，只有界面偏好另外存在 `%LocalAppData%\MineDeck`。
- 测 A-08（升级）时，要另外准备一份用过 v2.6.1 的文件夹的**副本**（先整个复制一份，在副本上测）。

### 2.2 测试用的服务器

在 MineDeck 里建好：

- **S1**：NeoForge 1.21.1。用「新建服务器」的向导建，再从「资源」标签装一两个模组（比如 JEI）。
- **S2**：Forge 1.20.1。用「新建服务器」导入一个整合包，最好是好友平时玩的那个。
- **S3**（可选，测 F-06）：1.21.5 或更新的版本，比如原版或 Paper 的最新版。
- **S4**（可选，测 F-07）：Paper、Fabric 或 Mohist。

### 2.3 游戏客户端

- 用 HMCL 或 PCL2 装好和 S1、S2 一样的版本和加载器。
- 新建的服务器默认关了正版验证，所以离线账号也能进。
- 测 [两个号] 的项时，可以在同一台电脑上开两个客户端，用不同的名字登录。

### 2.4 AI Key

- 至少两家。推荐 DeepSeek 和通义千问（阿里云百炼），国内能直接连，也便宜；能连上的话再加 Claude 或 OpenAI。
- 每家充值 10 元以内就够测完。
- Key 由用户本人填进 MineDeck 的界面，不要发给别人，也不要写进报告。

### 2.5 其他

- **Simple Voice Chat**（SVC）：测音乐共享（G 组）用。服务器和每个客户端都要装同一个版本，从 Modrinth 下载。
- **樱花穿透账号**：建一条 TCP 隧道给游戏用（C-03），一条 UDP 隧道给语音用（G-07）。
- **手机**：和电脑连同一个 Wi-Fi，测局域网访问。

### 2.6 程序目录里的文件

检查结果时会用到，路径都是相对 `MineDeck.exe` 所在的文件夹。

| 路径 | 是什么 |
|---|---|
| `config.json` | 全局设置 |
| `secrets.json` | 加密保存的密钥，值以 `dpapi:` 开头 |
| `tunnels.json` | 内网穿透的隧道 |
| `logs\ops\<年-月>.jsonl` | 操作记录，一行一条，带来源（ui / lan / assistant / gamechat / companion / schedule） |
| `data\ai\settings.json` | AI 设置（不含 Key） |
| `data\ai\usage.json`、`data\ai\prices.json` | AI 用量、价格缓存 |
| `data\ai\sessions\` | 应用内助手的会话 |
| `data\music\settings.json` | 音乐共享的设置 |
| `data\mcp\settings.json`、`data\mcp\runtime.json` | MCP 接口的开关；打开时运行着的 MineDeck 写的端口和进程号（给 `MineDeck.exe -mcp` 用，里面没有令牌） |
| `servers\<实例>\` | 服务器（默认位置，可以在设置里改） |
| `servers\<实例>\gameai.json`、`gameai-state.json` | 游戏内 AI 的设置、当天的次数和最近的问答 |
| `servers\<实例>\config\minedeck\voicebridge.properties` | 音乐桥接模组的配置 |
| `servers\<实例>\config\minedeck\companion.properties` | 伙伴模组的配置 |
| `runtimes\` | 自动下载的 Java、frpc |
| `%LocalAppData%\MineDeck\WebView2` | 界面偏好（主题、配色、控制台命令历史） |

MineDeck 窗口版没有单独的运行日志文件。出问题时请提供截图、操作记录，以及服务器的 `logs\latest.log` 和 `crash-reports\`。

## 3. 给 AI 测试员的说明

如果你是在用户电脑上帮忙测试的 AI（Claude、ChatGPT 或国内的智能体），请遵守下面几条：

1. **只动测试的东西**：只动测试文件夹（比如 `D:\MineDeck-beta`）和里面的服务器。不删别的文件，不改系统设置；要放行防火墙或改注册表时，先问用户。
2. **能自己核对的就自己核对**：
   - 第 2.6 节里的文件内容；
   - 进程（`Get-Process java, frpc`）；
   - 网络连接（`Get-NetTCPConnection`、`Get-NetUDPEndpoint`）；
   - 开机自启的注册表（`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`）；
   - 服务器的 `logs\latest.log`。
3. **要人来做的，请人做**：游戏里的操作、听声音、手机扫码、第二个账号、远程好友。把步骤写清楚交给用户，做完再记录结果，不要猜。
4. **Key 和密码不经你的手**：请用户自己填进界面。报告里不出现 API Key、密码和令牌；路径里的 Windows 用户名写成 `<用户名>`。
5. **发现问题先记录，不要绕过**：记下现象和复现步骤就继续下一项。不要改 MineDeck 的代码或配置去让测试通过，测试项要求改的除外。
6. **按顺序测**：按 A 到 J 的顺序，后面的项会用到前面建好的服务器和设置。条件不具备的项记「没法测」，写明缺什么。
7. **写报告**：每项一条，用第 5 节的格式；最后按第 6 节给一张汇总表。

## 4. 测试项

### A. 安装、升级和界面

**A-01 第一次运行（P0）** [Win11]
- 步骤：双击测试文件夹里的 `MineDeck.exe`。如果出现「Windows 已保护你的电脑」，点「更多信息 → 仍要运行」。
- 预期：
  - 窗口打开，播一次约 1 秒的启动画面（方块拼出图标），点击或按任意键能跳过；
  - 出现首次运行的引导卡（用户协议、下载源、存放位置）；
  - 文件夹里多了 `config.json` 等文件。

**A-02 窗口操作（P0）** [Win11]
- 步骤：拖动标题栏，双击标题栏，用右上角的最小化、最大化和关闭。
- 预期：
  - 拖动、最大化、还原都正常；
  - 关闭后窗口缩到托盘，服务器不停；
  - 托盘图标右键有「打开面板」和「全部停止并退出」。

**A-03 白闪（P1）** [Win11]
- 步骤：
  1. 把 Windows 分别设成浅色、深色，各冷启动一次 MineDeck。
  2. 在「设置 → 外观」换一套配色，关掉程序（托盘的「全部停止并退出」）再打开。
- 预期：
  - 从窗口出现到界面画出，不闪白；
  - 窗口底色和新配色的标题栏颜色一致。
- 已知情况：窗口刚出现的 0.1–0.3 秒可能还看得到系统标题栏或空白，这一项不算失败，但请记下来。

**A-04 跟随系统主题（P1）** [Win11]
- 步骤：「设置 → 外观」选「跟随系统」，再到 Windows 设置里切换浅色和深色。
- 预期：MineDeck 跟着切换，不用重启。

**A-05 字体（P1）** [Win11]
- 步骤：在 Windows 的显示缩放 100%、125%、150% 下分别看界面。
- 预期：
  - 中文、西文和控制台里的等宽字都清晰；
  - 正文、小标题、标题三档粗细分得开；
  - 在任意输入框里打「堃」「喆」这类生僻字，不显示成方框（由系统字体补上）。

**A-06 圆角和图标（P2）** [Win11]
- 步骤：
  1. 看卡片和按钮的圆角。
  2. 在「设置 → 应用 → 已安装的应用」里查 Microsoft Edge WebView2 Runtime 的版本号。
  3. 在 100%、125%、150%、200% 缩放下，看任务栏、托盘、Alt+Tab 和资源管理器里 exe 的图标。
- 预期：
  - 圆角是平滑过渡的「方圆」形；WebView2 太旧时回退成普通圆角，也算正常，记下版本号即可；
  - 图标都清晰，125% 下的托盘图标可能略糊。

**A-07 启动画面的规则（P2）** [Win11]
- 步骤和预期：
  - 按 F5 刷新、从托盘恢复窗口，都不再播启动画面；
  - 在 Windows「设置 → 辅助功能 → 视觉效果」里关掉动画效果后，冷启动不播；
  - 按 1–4 跳过启动画面时，不会顺带切页。

**A-08 从 v2.6.1 升级（P0）** [旧版]
- 步骤：在旧版文件夹的副本里放进 `MineDeck.exe`，退出正在运行的 AutoMCHUB，然后运行 MineDeck。
- 预期：
  - 服务器列表、设置都在；主题、配色和控制台命令历史还在；
  - 出现 `%LocalAppData%\MineDeck\WebView2`，`%AppData%\AutoMCHUB.exe` 消失；
  - 旧版填过 CurseForge Key 的：`config.json` 里没有 `cfApiKey` 了，出现 `secrets.json`，值以 `dpapi:` 开头；「设置 → 下载与网络」显示「已设置」；
  - 旧版有隧道的：`tunnels.json` 里的凭据变成 `dpapi:…`，隧道照常能启动；
  - 旧版开了开机自启的：注册表 Run 键下的 `AutoMCHUB` 值被删掉，开机自启变成关闭。

**A-09 密钥换了电脑解不开（P1）**
- 步骤：把填过 CurseForge Key 的整个测试文件夹，拷到另一台电脑或另一个 Windows 用户下运行。
- 预期：设置页提示「密钥无法解开」，让你重填；不会把乱码当成 Key 用。

### B. 开服和管理（原有功能的回归）

这一版改了所有接口的内部实现，原有功能要过一遍。

**B-01 新建 NeoForge 1.21.1（P0）**
- 步骤：「新建服务器」→ 选 NeoForge → 1.21.1 → 选构建 → 勾选 EULA → 创建。
- 预期：自动下载 Java 和服务端、跑完安装器，部署进度走完，服务器出现在列表里（这就是 S1）。

**B-02 导入整合包（P0）**
- 步骤：
  1. 「新建服务器」导入一个 Forge 1.20.1 的整合包（这就是 S2）。
  2. CurseForge 的 zip 包要先在「设置 → 下载与网络」填 CurseForge API Key；Modrinth 的 `.mrpack` 不用。
- 预期：自动认出核心和版本，模组下载完整，纯客户端的文件被跳过。

**B-03 启动和进服（P0）** [客户端]
- 步骤：
  1. 启动 S1，等控制台出现 `Done (...)!`。
  2. 客户端连 `127.0.0.1:端口`。
  3. 第一次启动时 Windows 防火墙弹窗，选「允许访问」。
- 预期：
  - 能进服，在线列表出现你的名字；
  - 「停止」后 30 秒内关好，`java.exe` 不残留。

**B-04 控制台（P1）**
- 步骤和预期：
  - 发 `say 你好`，游戏里看得到；
  - 按 ↑↓ 翻出命令历史，按 Tab 补全在线玩家名；
  - WARN 和 ERROR 行有颜色，过滤能用；
  - 老整合包出现乱码时，切换 GBK / UTF-8 能修好。

**B-05 玩家（P1）** [客户端]
- 步骤和预期：
  - 在「玩家」标签里给自己 OP、取消 OP、踢出，都生效；
  - 白名单、封禁名单的增删在开服和停服时都生效（停服时直接改名单文件）。

**B-06 备份（P1）**
- 步骤：运行中点备份，然后停服还原这份备份。
- 预期：运行中能热备；还原后世界回到备份时的状态。

**B-07 定时任务和崩溃重启（P2）**
- 步骤：
  1. 建一个一两分钟后执行的定时命令（比如 `say 定时`），看它执行。
  2. 打开崩溃自动重启，在任务管理器里结束服务器的 `java.exe`。
- 预期：
  - 定时命令按时执行；
  - 结束 `java.exe` 后服务器自动重启；
  - `logs\ops` 里有来源是 schedule 的记录。

**B-08 资源、配置和内存（P1）**
- 步骤和预期：
  - 在「资源」标签里搜索并装一个模组，文件进 `mods`；
  - 在「常用设置」改最大人数、「全部配置」改 MOTD，`server.properties` 跟着变；
  - 「内存 / 启动」改内存，下次启动生效。

**B-09 伪造进服（P1）** [客户端]
- 步骤：在游戏聊天里发「Notch joined the game」。
- 预期：
  - 在线列表不出现 Notch；
  - 正常进出服时在线人数照常变化；配了 Webhook 的话，一次进服只推一次 `player.join`。

**B-10 控制台中文（P0）**
- 步骤：在中文 Windows 上启动 S1（NeoForge 1.21.1，用 Java 21），再启动 S2 和别的核心的服务器，看控制台；在游戏里用中文聊天。
- 预期：
  - 模组日志和玩家聊天里的中文都正常，不是问号、不是乱码；
  - 控制台顶部的「编码」手动选成 gbk 的服务器，重启后中文也正常。
- 说明：这一版起，MineDeck 启动服务器时让 Java 18 以上的控制台输出一律用 UTF-8。以前在中文 Windows 上，Java 21 的服务器输出 GBK，短句有时会被认错。

**B-11 操作记录（P1）**
- 步骤：在界面上改几项设置、启停一次服务器，然后打开 `logs\ops\<年-月>.jsonl`。
- 预期：
  - 每次操作都有一行，来源是 ui；
  - 搜不到 CurseForge Key、Webhook 地址、`rcon.password` 的原文（写成 `***`）。

### C. 联机：局域网、手机和内网穿透

**C-01 局域网好友进服（P0）** [好友]
- 步骤：同一局域网的好友用 `你的内网IP:端口` 连进来。
- 预期：能进服。进不来时，先确认防火墙已放行 java。

**C-02 手机管理（P1）** [手机]
- 步骤：
  1. 「设置 → 远程访问」打开局域网访问并设密码。
  2. 用手机扫二维码，登录后启停服务器、发命令、改一项设置。
- 预期：
  - 二维码能识别，登录后能操作；
  - 侧栏变成底部标签栏；iPhone 的 Safari 上圆角回退成普通圆角，不播启动画面；
  - `logs\ops` 里这些操作的来源是 lan，actor 是手机的地址；
  - 「设置 → AI（可选）」只能看不能改，看不到 Key。

**C-03 樱花穿透：游戏隧道（P0）** [樱花] [好友]
- 步骤：
  1. 在樱花后台建 TCP 隧道，本地端口填 S1 的端口。
  2. 在「内网穿透」里添加：用途选「游戏」，绑定 S1，打开「跟随实例启动」。
  3. 启动 S1，把公网地址发给远程好友。
- 预期：
  - 隧道自动启动并显示公网地址，一键复制能用；
  - 远程好友能进服；
  - 停服时隧道跟着停。

**C-04 OpenFrp 和自定义 frps（P2）**
- 步骤：各建一条隧道，启动一次。
- 预期：
  - 都能连上；

  - 给东西：背包里不够时，AI 直接说只有几个、不够（没开始干活），或者让伙伴先去弄；给够了才说「做完了」，一个都没给出去时私下收到「……失败了：交出了 0 个（要 5 个）……」和原因（比如「原来只有 2 个，也没弄到更多」「Alex 不在伙伴所在的维度」），只给了一部分时是「没做够」（伙伴模组 0.2.1 起；0.2.0 会说「做完了：交出了 0 个」）。

**H-07 规则（P1）** [客户端]
- 预期：
  - 让伙伴打村民：被拒绝，AI 照实转告；
  - 禁挖区域里的方块，伙伴不拆不放；绕不过去时「最近的事件」里有「卡住了」。

**H-08 好友的整合包（P1）** [客户端]
- 步骤：在 S2（好友的整合包）上做 H-03、H-04。
- 预期：伙伴寻路不会被模组的方块卡死，和别的模组不冲突；整合包本来就带 Architectury 时，安装不动它。

**H-09 报错横幅不误报（P1）**
- 预期：
  - 装了 PlayerEngine 的服务器正常启动后，不出现「客户端模组放进了服务端」；
  - 再放进一个小地图模组，照样认出来，而且只点名那个小地图。

**H-10 好友的客户端（P0）** [好友]
- 步骤：
  1. 在「伙伴」标签点「复制给好友的说明」，发给好友。
  2. 好友照着装：客户端只装伙伴模组，加上整合包本来的模组。伙伴模组的文件也可以从发布页下载，选和服务器对应的那个。
- 预期：
  - 好友能进服，看得到伙伴；
  - 没装伙伴模组的好友，登录时看到中文提示。

**H-11 断线重连（P2）**
- 步骤：伙伴干活时，把 `companion.properties` 里的端口改掉再改回来。
- 预期：MineDeck 自动重连；断开期间做完的任务照样通知发起的人。

### I. 退出、开机自启和更新

### J. MCP 接口（外部 AI 工具）

让电脑上的其他 AI 工具经 MCP 用 MineDeck。不需要先配 MineDeck 自己的 AI 服务商（D-01）。MCP 客户端调用工具前可能先问你是否允许，这是客户端自己的确认，照常同意；写操作在 MineDeck 里还要再确认一次。

**J-01 默认关闭（P0）**
- 步骤：
  1. 打开「设置 → AI（可选）」，找到「MCP 接口」。
  2. 在 PowerShell 里运行：`Invoke-WebRequest -Method Post -Uri http://127.0.0.1:27333/mcp -Body '{}' -ContentType application/json`。
- 预期：
  - 开关是关的；
  - 请求被拒（403），回的内容里有「MCP 接口没有打开」；
  - 程序目录下没有 `data\mcp\runtime.json`，`secrets.json` 里没有 `mcp.token`。

**J-02 打开和令牌（P0）**
- 步骤：打开「MCP 接口」的开关。
- 预期：
  - 出现接口地址、访问令牌（只说已生成，不显示）、「复制配置…」；
  - `secrets.json` 里有 `"mcp.token": "dpapi:…"`；
  - `data\mcp\runtime.json` 出现，里面有 `pid` 和 `port`，没有令牌；
  - `logs\ops` 里有一条 `mcp.set`。

**J-03 Claude Desktop：stdio（P0）** [MCP 客户端]
- 步骤：
  1. 「复制配置… → Claude Desktop」，按弹窗里的说明粘进 `claude_desktop_config.json`，完全退出再打开 Claude Desktop。
  2. 在 Claude 里问「MineDeck 里有哪些服务器？S1 最多能进几个人？」
- 预期：
  - Claude 的工具列表里有 MineDeck 的工具（50 多个），回答正确；
  - 工具结果里的路径是 `<程序目录>` 这类占位，看不到 Windows 用户名；
  - MineDeck 的「连过的 AI 工具」里出现 Claude（stdio），调用次数在涨；
  - 任务管理器里有 `MineDeck.exe -mcp` 进程，没有窗口；Claude 启动它时，鼠标不会一直转圈（转了的话记下大概几秒）。

**J-04 写操作要在 MineDeck 里确认（P0）** [MCP 客户端]
- 步骤：让 Claude「把 S1 的最大人数改成 10」。
- 预期：
  - Claude 说已经提交、要你去 MineDeck 里确认，没说已经改好；
  - MineDeck 弹出提示「外部 AI「…」请求：修改 server.properties」，标题栏的「AI 助手」亮小方块；
  - 点提示打开面板，顶上「外部 AI 的请求」里有确认卡片，写明改前改后、是哪个 AI 工具提的；
  - 确认后 `server.properties` 里是 `max-players=10`；`logs\ops` 里这条的 `src` 是 mcp，`actor` 是 Claude 报的名字，`approvedBy` 是本机；
  - 让 Claude 查一下结果（它会调 proposal_status），它说已经执行。

**J-05 拒绝、危险操作、EULA、关掉（P1）** [MCP 客户端]
- 步骤和预期：
  - 拒绝一张卡片并写理由：Claude 查结果时说你拒绝了，并提到理由；
  - S1 运行中让它「重启 S1」：卡片标「危险操作」，多勾一次才能确认；S1 停着时它会直接告诉你服务器没在运行，不出卡片；
  - 让它「新建一台 Paper 1.21.4 的服务器」：卡片上的 EULA 要你自己勾，Claude 没法替你同意；
  - 有卡片没处理时关掉 MCP 开关：卡片消失；Claude 再查，说你关闭了 MCP 接口。

**J-06 HTTP 方式：Cherry Studio、Cursor、VS Code（P0）** [MCP 客户端]
- 步骤：有哪个就测哪个。「复制配置…」选对应的一项，按说明粘贴；再做一次 J-03 的提问和 J-04 的修改。
- 预期：
  - 能列出工具、调用读工具、提交写操作；
  - 「连过的 AI 工具」里显示 HTTP 和协议版本，把每家显示的协议版本记下来；
  - 弹窗里的「粘贴到哪儿」和这个工具实际的菜单对得上（对不上的话记下实际的位置）。

**J-07 令牌和只限本机（P0）**
- 步骤：
  1. 点「重置令牌」，然后让 HTTP 方式的工具（不改配置）和 Claude Desktop 各调用一次。
  2. 把 HTTP 方式那个工具的配置里的令牌改错一位，再调用。
  3. 局域网访问开着时，用手机打开「设置 → AI」；再用手机或另一台电脑访问 `http://<主机 IP>:27333/mcp`。
- 预期：
  1. HTTP 方式的报「令牌不对」，重新复制配置后恢复；Claude Desktop（stdio）不受影响。
  2. 同样报「令牌不对」。
  3. 手机上「MCP 接口」只能看，没有令牌和复制配置，也收不到外部 AI 的请求；从别的设备访问 `/mcp` 被拒（403）。

**J-08 MineDeck 没开、重启（P1）** [MCP 客户端]
- 步骤：
  1. 退出 MineDeck（托盘的「全部停止并退出」），在 Claude 里让它查服务器。
  2. 再打开 MineDeck，不重启 Claude，让它接着查。
- 预期：
  1. Claude 很快收到「没有找到运行着的 MineDeck……」，不会一直转圈；`%APPDATA%\Claude\logs\` 下这个服务器的日志里有同样的中文提示；`data\mcp\runtime.json` 已经删掉。
  2. 能接着用；之后提交的写操作，卡片上写的还是 Claude 的名字。

**J-09 端口被占用（P2）**
- 步骤：先占住 27333（比如在别的文件夹再开一个 MineDeck），再启动这一个。
- 预期：「MCP 接口」里写明端口被占用、HTTP 方式的配置要改；HTTP 方式的旧配置连不上；stdio 方式不受影响。

**J-10 命令行直接跑 -mcp（P0）**
- 步骤：MineDeck 开着、MCP 打开时，在测试文件夹里打开 PowerShell，运行：
  `'{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"ps","version":"1"}}}' | .\MineDeck.exe -mcp`
- 预期：打印一行 JSON（里面有 `"protocolVersion":"2025-06-18"` 和 `"name":"minedeck"`），然后进程自己退出；没有弹出任何窗口。这一项验证 GUI 子系统的 exe 在 Windows 上能读写管道。

## 5. 反馈格式

一个问题写一条，通过的项也可以只在汇总表里写「通过」。

```
【编号】F-08（没有编号就写在做什么）
【结果】不通过 / 部分通过 / 没法测（写缺什么）
【版本】v2.9.0-beta.2（「设置 → 更新与关于」里看）
【电脑】Windows 11 24H2（Win+R 输入 winver 看），内存 16 GB
【服务器】NeoForge 1.21.1-21.1.xxx，整合包名（没有就不写）
【AI】服务商和模型（不要写 Key）
【步骤】
1. …
2. …
【预期】…
【实际】…
【附件】截图或录屏；logs\ops 里相关的几行；服务器的 logs\latest.log、crash-reports\；客户端的 latest.log
```

- 发到公开的地方（比如 GitHub Issue）之前，把日志里的 Windows 用户名、IP 地址换掉。
- 任何时候都不要贴 API Key、局域网密码和樱花的访问密钥。
- 客户端日志一般在 `.minecraft\logs\latest.log`；HMCL、PCL2 开了版本隔离时在 `.minecraft\versions\<版本名>\logs\latest.log`。
