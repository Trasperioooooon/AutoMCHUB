最后更新：2026-10-28。这份文件写给接手的 AI，不管是云端会话还是别的平台，也方便用户自己回顾。这里只记当前进度和还没解决的问题，已经做完的事以 git 历史为准。

## 现在的状态

main 分支包含四部分内容：

- PR #2 的 UI 常规化改版 v4，以及当时一起合入的七个修复分支。
- 和 v4 配套的新应用图标，以及前端开发工具 `tools/ui-dev`。
- 项目改名：AutoMCHUB 正式改为 MineDeck。
- 改名后的兼容处理：删除旧版的开机自启项；WebView2 数据目录固定下来，并迁移旧目录（见下文）。

改名的做法是对全仓做两条文本替换：AutoMCHUB 换成 MineDeck，automchub 换成 minedeck。Go module 因此变成了 `minedeck`，所有 import 都是 `minedeck/internal/...`。窗口标题、托盘、控制台前缀、下载 UA、frpc 代理名、开机自启的注册表值名、自更新用到的文件名和检查地址，以及 release.yml 的产物名（MineDeck.exe），都已经跟着改了。只有一批以 amh 开头的内部键名刻意没改，比如浏览器本地存储里的 amh_theme、amh_token 和登录 cookie amh_session，改了会让老用户的设置和登录失效。

GitHub 仓库已经从 Trasperioooooon/AutoMCHUB 改名为 Trasperioooooon/MineDeck。旧地址会被 GitHub 自动转到新地址，所以旧的克隆、旧链接，以及老版本程序里写死的更新地址都还能用。

程序里的版本号还是 2.6.1，新版本还没发布。

## 接手的第一步

如果你手上的分支是改名之前开的，代码已经过时了：那些 claude/ 分支在远端都已删掉，代码里也还没有改名。请先 `git fetch origin`，再切到 main 并更新到最新（`git switch main && git pull`）。之后的工作从 main 新开分支，不要再往旧分支上推。改名之后 module 名是 minedeck，写 import 和跑命令时都要注意这一点。

## 改名带来的三件事（已定）

**老用户的自动更新：不做过渡。** 用户说目前还没有外部用户，v2.6.1 的几次下载基本是自己下的。新版 Release 里只有 MineDeck.exe，v2.6.1 及更早的版本在 SHA256SUMS 里找不到 AutoMCHUB.exe 那一行，点更新会报「无法获取该版本的官方校验和……已取消更新」，只能手动下载一次新 exe。`release.yml` 不改。老配置里存的更新仓库还是 Trasperioooooon/AutoMCHUB，靠 GitHub 的改名重定向照样能用，也可以在「设置 → 更新」里改成新名。不要再新建叫 AutoMCHUB 的仓库，否则这个重定向会失效。

**开机自启：删除旧值。** 新版每次启动都会删掉注册表 Run 键下旧的 AutoMCHUB 值（`autostart.RemoveLegacy`）。所以升级后开机自启是关闭的，需要的话到设置里重新打开。

**界面偏好：数据目录固定。** 创建窗口时显式指定 WebView2 数据目录 `%LocalAppData%\MineDeck\WebView2`（见 `webviewdata_windows.go`），以后 exe 改名也不会丢主题、配色和控制台历史。这个目录还不存在时，先把旧的默认目录整体移过来：优先用 `%AppData%\<当前 exe 文件名>`，没有就用 `%AppData%\AutoMCHUB.exe`。移动失败（比如旧进程的 WebView2 还没退干净）就本次沿用旧目录，下次启动再试。多份安装共用这一套偏好。

## 只能在用户的 Windows 电脑上做的验证

v4 还没在真实的 Windows / WebView2 窗口里跑过，需要用户在本机确认这几项：

- 标题栏能不能拖动、最大化是否正常。
- 「设置 → 外观」里选「跟随系统」后，能不能随 Windows 主题切换。
- 用手机扫远程访问二维码能不能识别。
- 新图标在任务栏和托盘上的样子。
- 在用过 AutoMCHUB.exe 的电脑上第一次运行新版：主题、配色和控制台命令历史应该都还在，`%LocalAppData%\MineDeck\WebView2` 出现，`%AppData%\AutoMCHUB.exe` 消失。

## 测试和发版

后端用 `go test ./...` 测试，有测试的包有七个：根目录的 main，以及 app、autostart、events、inst、themes、web，在 Windows 上都应该通过。`go vet` 会报 `frameless_windows.go` 里一条 unsafe.Pointer 的问题，这是已知的误报，不用处理。

在 Linux 上（比如云端会话）只有 events 和 themes 的测试能直接跑，其余的要借 wine。Ubuntu 24.04 上先 `apt-get install wine64`（装在 `/usr/lib/wine/wine64`，不在 PATH 里），再运行：

```bash
LANG=C.UTF-8 GOOS=windows go test -exec /usr/lib/wine/wine64 ./...
```

一定要设 UTF-8 的 LANG，否则名字带中文的子测试会因为建不了临时目录而失败。2026-10-28 用这个办法跑过，七个包全部通过。

前端交互测试在 `tools/ui-dev`，用法见那里的 README；2026-10-28 跑过，24 条全部通过。

发版流程如下：

1. 改 `internal/app/app.go` 里的 Version 并提交。
2. 合入 main，打 `v` 开头的 tag。
3. 推送 main 和 tag。推 tag 会触发 CI，构建 MineDeck.exe 和 SHA256SUMS 并创建 Release。

打 tag 之前，先请用户在 Windows 上把上面几项验证做完。
