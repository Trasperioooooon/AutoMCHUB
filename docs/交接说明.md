GitHub 仓库已经从 Trasperioooooon/AutoMCHUB 改名为 Trasperioooooon/MineDeck。旧地址会被 GitHub 自动转到新地址，所以旧的克隆、旧链接，以及老版本程序里写死的更新地址都还能用。远端所有 claude/ 开头的分支都已删除，现在只剩 main。

程序里的版本号还是 2.6.1，新版本还没发布。

## 接手的第一步

如果你是之前做 UI v4 的那个云端会话，你手上的代码已经过时了。你所在的 claude/magical-galileo-ngby9c 分支在远端已经删掉，你的代码里也还没有改名。请先 `git fetch origin`，再切到 main 并更新到最新（`git switch main && git pull`）。之后的工作从 main 新开分支，不要再往旧分支上推。改名之后 module 名是 minedeck，写 import 和跑命令时都要注意这一点。

## 发版前要用户拍板的三件事

这三件事都是改名带来的，代码里都还没处理。

**老用户的自动更新。** v2.6.1 及更早版本是这样更新的：从 Release 的资产里取最后一个 .exe 下载，再去 SHA256SUMS 里找 AutoMCHUB.exe 那一行的哈希来校验。新版 Release 里只有 MineDeck.exe，老版本找不到这一行，就会安全地拒绝更新，老用户只能手动下载一次新 exe。想让他们无感升级，可以在过渡期的 Release 里额外附一份和 MineDeck.exe 字节完全相同的 AutoMCHUB.exe，并把它也写进 SHA256SUMS。这需要改 `.github/workflows/release.yml`。

**开机自启。** 注册表里的值名从 AutoMCHUB 改成了 MineDeck。老版本写下的 AutoMCHUB 值，新版既不认，也不清理。可以考虑让新版启动时把旧值迁移过来，或者直接删掉。

**界面偏好。** 代码没有指定 WebView2 的数据目录，go-webview2 默认用 `%AppData%\<exe 文件名>`。所以用户手动把 AutoMCHUB.exe 换成 MineDeck.exe 以后，浏览器本地存储会落到一个新目录，主题、配色、强调色和控制台历史都会回到默认。被旧版自动更新的用户，文件名没变，不受影响。要避免这个问题，就得在创建窗口时显式指定数据目录，并在首次启动时把旧目录迁移过来。

## 只能在用户的 Windows 电脑上做的验证

v4 还没在真实的 Windows / WebView2 窗口里跑过，需要用户在本机确认这几项：

- 标题栏能不能拖动、最大化是否正常。
- 「设置 → 外观」里选「跟随系统」后，能不能随 Windows 主题切换。
- 用手机扫远程访问二维码能不能识别。
- 新图标在任务栏和托盘上的样子。

## 测试和发版

后端用 `go test ./...` 测试，有测试的五个包都应该通过。`go vet` 会报 `frameless_windows.go` 里一条 unsafe.Pointer 的问题，这是已知的误报，不用处理。前端交互测试在 `tools/ui-dev`，用法见那里的 README；2026-10-28 在 main 上跑过，24 条全部通过。

发版流程如下：

1. 改 `internal/app/app.go` 里的 Version 并提交。
2. 合入 main，打 `v` 开头的 tag。
3. 推送 main 和 tag。推 tag 会触发 CI，构建 MineDeck.exe 和 SHA256SUMS 并创建 Release。

打 tag 之前，先把上面那三件事定下来。
